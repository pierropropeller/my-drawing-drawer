## 0. 一句話

自用、非社交的同人創作管理 App。以「坑」為單位，收藏官方圖與同人圖，並記錄自己「腦洞 → 草稿 → 成圖」的創作過程，設年／月目標追蹤進度。**Android 先行，之後出 iPad，兩邊資料經 Google Drive 同步。**

## 1. 產品原則（不可違反）

1. **Offline-first**：所有操作先寫本機，有網絡時自動上傳到 Google Drive；離線時首頁顯示橫條「離線中・恢復網絡後將自動上傳」。沒有手動備份按鈕。
2. **非社交**：沒有帳號系統、沒有分享牆。Google 帳號只用於 Drive 同步。
3. **介面文字一律書面語**（繁體中文，非粵語口語）：例如「上傳」不是「上載」、「今天」不是「今日」、「選擇」不是「揀」。
4. **用詞統一**
   - **關聯**：只用於腦洞、草稿、成圖之間的關係（「關聯腦洞」「關聯草稿」「關聯的成圖」）。**不要用「連接」。**
   - **連結**：只用於外部，即網址與 Google 帳號（「社交媒體連結」「連結 Google 帳號」「已連結」）。
   - **帳號**：不用「帳戶」。
   - **草稿**：不用「草圖」。
   - **新增 vs 選擇**：「新增」＝建立新東西（新增 tag、加圖）；「選擇」＝從已有項目挑（選擇腦洞／草稿／成圖／坑）。
   - 動詞：腦洞＝**生產**，草稿＝**畫**，成圖＝**完成**（例：「生產 20 個腦洞」「完成 12 張成圖」）。
5. **不放多餘說明小字**。Molly 明確不要卡片下的 description、表單的範例 placeholder。
6. **暫不做**：影片、圖片「移動」到其他分組／坑。
7. **多語言預備**：所有介面文字一律放進 Flutter 的 ARB 檔（`lib/l10n/app_zh_Hant.arb`），**不准把中文寫死在 widget 裡**。英文版之後加 `app_en.arb` 即可，跟隨系統語言。App 在桌面的名稱也要按語言顯示（Android 用 `values-zh-rTW/strings.xml` 與 `values/strings.xml`）。

## 3. 資料模型

所有實體都有：`id`（UUID，客戶端生成）、`createdAt`、`updatedAt`、`deletedAt`（軟刪除，供同步用）、`deviceId`（最後修改的裝置）。

### 3.7 Tag
- `pitId`、`name`。**tag 按坑獨立，不同坑之間不共用。**
- 同一個坑內，同人圖、腦洞、草稿、成圖共用一套 tag。
- **角色不是獨立欄位**，一律以 tag 表示（例：`#角色1`、`#角色1×角色2`、`#夏日企劃`）。
- `TagManage`：可新增、改名、刪除；顯示使用次數。

### 3.8 目標 `Goal`
| 欄位 | 型別 | 備註 |
|---|---|---|
| period | `year` / `month` | |
| year, month? | int | |
| name | string? | 可空；空時自動生成（見下） |
| kind | `idea` / `draft` / `piece` | 必填 |
| count | int ≥ 1 | 必填 |
| pitId | id? | 目標坑（可空＝任意坑） |
| tagIds | id[] | **可選的 tag 依所選的坑而定**；未選坑時不能選 tag |
| requireLikes | int? | 只限 `piece`：「需要達成互動量」開啟後填數字 |

自動名稱：`{生產|畫|完成} {count} {個|份|張}{腦洞|草稿|成圖}`；有互動量條件時為「互動量過 {n} 的成圖 {count} 張」。

進度計算：期間內 `createdAt`（成圖用 `finishedAt`）落在期間、符合坑／tag、成圖符合互動量門檻的數量。

列表顯示：坑是一顆白色 pill（前面放封面小方塊），tag 每個獨立一顆灰色 pill。

### 3.9 年度回顧 `YearReview`
- `year`、每月一張精選圖 `monthImageId[12]`（可空）。
- 排版設定（`ReviewEdit`）：
  - 格數：1×12、2×6、3×4、4×3、6×2
  - 比例：1:1、4:3、3:4、9:16、16:9、2:1、1:2
  - 月份格式：Jan、January、一月、1月、01
  - 月份位置：**圖上**（直角正方形 12 格貼合，月份白字加陰影）或**空白位置**（格之間有 padding，白底黑字）
- 「儲存並匯出圖片」→ 輸出 PNG。

### 3.10 設定（不同步，跟裝置走）
- 主題：淺色／深色／跟隨系統（每台裝置各自設定）
- 前台自動刷新間隔：每 1／5／15／30 分鐘（預設 5）
- 自動同步：開／關

使用者資料（同步）：暱稱、頭像。

## 4. 同步設計（建議）

```
Drive/App 專用資料夾/
  meta/            ← 每筆實體一個 JSON（或按坑分檔）
  images/{id}.jpg  ← 原圖
  thumbs/{id}.jpg  ← 縮圖（可選，亦可本機生成）
```

- **寫入**：本機 DB 寫完，把變更放進 `outbox` 佇列；有網絡就依序上傳。圖片先傳，meta 後傳。
- **讀取**：App 在前台時按設定間隔拉取 Drive 變更（Drive Changes API／比對 `modifiedTime`），套用到本機。
- **衝突**：以實體為單位，`updatedAt` 較新者勝（last-write-wins）。只有一個使用者、兩台裝置，這樣夠用。
- **刪除**：軟刪除＋同步，過一段時間才真正清理。
- **離線提示**：首頁橫條，不用彈窗。
- **更換同步的 Google 帳號**：`Backup` 頁；切換前要提示本機資料將如何處理（建議：上傳到新帳號）。

| `MainSyncing` | 主頁 · 同步中 | 不用橫條；頭像外圈進度環，傳輸中可點開同步進度；未下載完的圖右下角進度環角標（D-052） |
| `SyncSheet` | 同步進度 | 總進度＋逐張上傳／下載進度（D-052） |
| `ReviewPick` | 年度回顧 · 選擇月份圖片 | 長按多於一張成圖的月份，選代表圖（D-056） |
| `MainEmpty` / `OfficialEmpty` / `IdeaEmpty` / `GoalEmpty` | 空白狀態 | 同人圖、草稿、成圖的空白頁沿用 `OfficialEmpty` 模板，只換顏色、icon、文字 |
| `MainDark` / `PitDark` / `IdeaListDark` | 深色模式示範 | 其他畫面依第 7 節對照表轉換 |

## 6. 互動規則

- **排序**：所有列表預設「最後更新最前」。
- **目標排序**：按進度由高至低排列，已達成（100%）的沉到最底。
- **下載**：存到獨立相簿（Android：`Pictures/Drawer`），不要混入相機膠卷。
- **坑內五格固定排序**：官方圖冊、好看同人圖、我的草稿、我的腦洞、我的成圖。
- **長按**：坑內頁的格子 → 選擇封面；官方圖冊的圖 → 多選。
- **底部導覽列**：坑／目標／我的。目前所在分頁的 icon 與文字都用主色、字重 700；子頁面跟隨所屬分頁亮起。
- **哪些頁面有導覽列**（以 artboard 為準，有畫 `<nav>` 才有）：
  - **有**：主頁、坑內頁、五個列表頁（官方圖冊、同人圖、草稿列表／九宮格、腦洞、成圖）、目標（年／月／日）、我的、空白狀態頁。
  - **沒有**：所有新增／編輯頁、詳情頁、圖片預覽、多選、管理分組、管理 tag、選擇封面、年度回顧排版、主題、備份與同步、登入流程。
  - 簡單規則：**瀏覽用的頁面有，做事用的頁面（填表、看單一項目、選取、設定）沒有。**
- **表單的 tag 欄**旁有「管理」→ `TagManage`。
- **選中狀態**統一：2px 主色框＋22px 實心主色圓圈白剔。
- **圓角**：文字卡片 16px、圖片格 12px、chips 999px、按鈕 14px。
- **刪除**一律要確認（設計稿未畫確認框，用系統 dialog 或 bottom sheet；**popup 不要頂部小橫杆**）。
