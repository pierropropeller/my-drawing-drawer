## 0. 一句話

自用、非社交的同人創作管理 App。以「坑」為單位，收藏官方圖與同人圖，並記錄自己「腦洞 → 摸魚 → 成圖」的創作過程，設年／月目標追蹤進度。**Android 先行，之後出 iPad，兩邊資料經 Google Drive 同步。**

## 1. 產品原則（不可違反）

1. **Offline-first**：所有操作先寫本機，有網絡時自動上傳到 Google Drive；離線時首頁顯示橫條「離線中・恢復網絡後將自動上傳」。沒有手動備份按鈕。
2. **非社交**：沒有帳號系統、沒有分享牆。Google 帳號只用於 Drive 同步。
3. **介面文字一律書面語**（繁體中文，非粵語口語）：例如「上傳」不是「上載」、「今天」不是「今日」、「選擇」不是「揀」。
4. **用詞統一**
   - **關聯**：只用於腦洞、摸魚、成圖之間的關係（「關聯腦洞」「關聯摸魚」「關聯的成圖」）。**不要用「連接」。**
   - **連結**：只用於外部，即網址與 Google 帳號（「社交媒體連結」「連結 Google 帳號」「已連結」）。
   - **帳號**：不用「帳戶」。
   - **摸魚**：不用「草圖」。
   - **新增 vs 選擇**：「新增」＝建立新東西（新增 tag、加圖）；「選擇」＝從已有項目挑（選擇腦洞／摸魚／成圖／坑）。
   - 動詞：腦洞＝**生產**，摸魚＝**畫**，成圖＝**完成**（例：「生產 20 個腦洞」「完成 12 張成圖」）。
5. **不放多餘說明小字**。Molly 明確不要卡片下的 description、表單的範例 placeholder。
6. **影片與 GIF**：全部圖片欄位都支援（D-080，見 3.13）。
7. **多語言預備**：所有介面文字一律放進 Flutter 的 ARB 檔（`lib/l10n/app_zh_Hant.arb`），**不准把中文寫死在 widget 裡**。英文版之後加 `app_en.arb` 即可，跟隨系統語言。App 在桌面的名稱也要按語言顯示（Android 用 `values-zh-rTW/strings.xml` 與 `values/strings.xml`）。

## 3. 資料模型

所有實體都有：`id`（UUID，客戶端生成）、`createdAt`、`updatedAt`、`deletedAt`（軟刪除，供同步用）、`deviceId`（最後修改的裝置）。

### 3.7 Tag
- `pitId`、`name`。**tag 按坑獨立，不同坑之間不共用。**
- 同一個坑內，同人圖、腦洞、摸魚、成圖共用一套 tag。
- **角色不是獨立欄位**，一律以 tag 表示（例：`#角色1`、`#角色1×角色2`、`#夏日企劃`）。
- `TagManage`：可新增、改名、刪除；顯示使用次數。

### 3.8 目標 `Goal`
| 欄位 | 型別 | 備註 |
|---|---|---|
| period | `year` / `month` | |
| year, month? | int | |
| name | string? | 可空；空時自動生成（見下） |
| kind | `idea` / `draft` / `piece` | 必填 |
| count | int ≥ 1 | 必填 |
| pitId | id? | 目標坑（可空＝任意坑） |
| tagIds | id[] | **可選的 tag 依所選的坑而定**；未選坑時不能選 tag |
| requireLikes | int? | 只限 `piece`：「需要達成互動量」開啟後填數字 |

自動名稱：`{生產|畫|完成} {count} {個|份|張}{腦洞|摸魚|成圖}`；有互動量條件時為「互動量過 {n} 的成圖 {count} 張」。

進度計算：期間內 `date`（腦洞、摸魚；成圖用 `finishedAt`）落在期間、符合坑／tag、成圖符合互動量門檻的數量。

列表顯示：坑是一顆白色 pill（前面放封面小方塊），tag 每個獨立一顆灰色 pill。

### 3.9 年度回顧 `YearReview`
- `year`、每月一張精選圖 `monthImageId[12]`（可空）。
- 排版設定（`ReviewEdit`）：
  - 格數：1×12、2×6、3×4、4×3、6×2
  - 比例：1:1、4:3、3:4、9:16、16:9、2:1、1:2
  - 月份格式：Jan、January、一月、1月、01
  - 月份位置：**圖上**（直角正方形 12 格貼合，月份白字加陰影）或**空白位置**（格之間有 padding，白底黑字）
- 「儲存並匯出圖片」→ 輸出 PNG。

「我喜歡這個角色」的足跡，不屬於創作線，**不和腦洞／摸魚／成圖建立任何關聯**，不計入目標、不入目標時間軸。
| 欄位 | 型別 | 備註 |
|---|---|---|
| pitId | id | |
| date | date | 必填。預設取**第一張圖**的拍攝時間（EXIF `DateTimeOriginal`），沒有就用檔案修改時間，再沒有就用今天；可手動改 |
| images | Media[] | 至少一張；一筆紀錄＝一個事件；圖片／GIF／影片都可以（D-080） |
| groupId | id? | 單選，見 `OshiGroup`；可不分組 |
| title | string? | 選填 |
| description | string? | 選填，時間軸卡片顯示最多兩行 |
| tags | Tag[] | 沿用坑內 tag（按坑獨立） |

- `OshiGroup`：`pitId`、`name`、`sortOrder`。**按坑獨立**；新坑預設三個：線下照片、遊戲截圖、對話記錄，可新增、改名、刪除、排序（沿用 `GroupManage` 樣式）。
- 沒有「類型」、沒有「可展示」（D-062 拿掉）。
- 計數單位：「筆」。

### 3.12 素材庫 `Material`（D-071）
畫畫參考用的圖，**不屬於任何坑**，入口在「我的」。只有圖，**沒有任何文字欄位**（無標題、描述、tag）。
| 欄位 | 型別 | 備註 |
|---|---|---|
| image | file | 一筆＝一張圖 |
| category | enum | 單選：服裝、姿勢、人體、色盤、場景、畫風、貼圖（先固定這 7 個） |
| createdAt | datetime | 排序用，新的在前 |

- 不計入目標、不入時間軸、不和坑內任何東西建立關聯。
- 版面偏好（瀑布／九宮格）存在裝置設定（3.10）。

### 3.13 媒體 `Media`（D-080）
所有放圖的地方（官方圖冊、同人圖、腦洞配圖、摸魚、成圖、推活、雜物、素材庫）都用同一個型別。
| 欄位 | 型別 | 備註 |
|---|---|---|
| kind | enum | `image`／`gif`／`video`，按檔案 MIME 判斷 |
| file | file | 原檔，不轉檔 |
| width／height | int | 詳情頁算圖片框比例用（D-073） |
| durationMs | int? | 只限影片 |
| poster | file? | 影片第一格截圖（本機產生、也同步），列表縮圖用 |
| sensitive | bool | 敏感內容標記，預設 false（D-104）。只在總開關＋該坑開關都開時生效 |

- 需要靜態圖的地方（坑封面、年度回顧、月曆格、分享卡縮圖）：GIF 用第一格，影片用 `poster`。
- 同步：影片檔大，上傳沿用同步佇列；〔待評估〕「影片只在 Wi-Fi 上傳」開關。

### 3.10 設定（不同步，跟裝置走）
- 主題：淺色／深色／跟隨系統（每台裝置各自設定）
- 前台自動刷新間隔：每 1／5／15／30 分鐘（預設 5）
- 自動同步：開／關
- App 圖示：`sanbi`／`huati`（D-086）
- 敏感內容標記 `sensitiveEnabled`（預設關）、安全模式 `safeMode`（預設開）（D-104）

使用者資料（同步）：暱稱、頭像。存在資料庫 `user_profiles`（單列，id=`me`，`updatedAt` 較新者勝），同步種類 `profile`；
頭像檔跟其他圖片一起上傳／下載（排在下載清單最前面）。設定裡另存一份只為啟動時立刻顯示；頭像檔還沒下載到時顯示暱稱第一個字。

## 4. 同步設計（建議）

```
Drive/App 專用資料夾/
  meta/            ← 每筆實體一個 JSON（或按坑分檔）
  images/{id}.jpg  ← 原圖
  thumbs/{id}.jpg  ← 模糊占位圖（必做，長邊 32px、約 1KB，D-099；本機 480 列表縮圖不同步）
```

- **寫入**：本機 DB 寫完，把變更放進 `outbox` 佇列；有網絡就依序上傳。圖片（占位圖＋原圖）先傳，meta 後傳。
- **下載次序**：meta → 全部占位圖 → 原圖（D-099）。同步 sheet 每行要有縮圖和「坑 · 格」位置。
- **讀取**：App 在前台時按設定間隔拉取 Drive 變更（Drive Changes API／比對 `modifiedTime`），套用到本機。
- **使用者資料**：暱稱、頭像是單例文件 `meta__profile__me.json`（schema v12）；舊版 App 不認得此種類會直接忽略，`syncFormatVersion` 不變。
- **縮圖補傳**：每次同步，本機有原圖、雲端沒有 `thumbs__` 的由這台補產生並上傳（最近加入的優先，每次最多 150 張或 60 秒）；縮圖下載階段最多 20 秒，沒下載完的下次接著；結果的 `thumbsStillMissing` 與同步 log 會顯示仍缺幾張。
- **衝突**：以實體為單位，`updatedAt` 較新者勝（last-write-wins）。只有一個使用者、兩台裝置，這樣夠用。
- **刪除**：軟刪除＋同步，過一段時間才真正清理。
- **離線提示**：首頁橫條，不用彈窗。
- **更換同步的 Google 帳號**：`Backup` 頁；切換前要提示本機資料將如何處理（建議：上傳到新帳號）。

## 6. 互動規則

- **排序**：所有列表預設「最後更新最前」。
- **目標排序**：按進度由高至低排列，已達成（100%）的沉到最底。
- **下載**：存到獨立相簿（Android：`Pictures/Drawer`），不要混入相機膠卷。
- **坑內六格固定排序**（2 欄 3 列，全部正方形）：官方圖冊、好看同人圖／我的腦洞、我的摸魚／我的成圖、推活（D-074）。
- **長按**：坑內頁的格子 → 選擇封面；列表裡的圖／卡片 → 多選。**長按後不放手直接拖曳＝連續多選**（D-081）。
- **時間軸的月份標題**捲動時置頂（D-077）。
- **加圖一律用自家圖片選擇器**（D-084），不用系統選圖；選的順序＝帶回表單的順序。
- **表單裡的圖片排序**：長按浮起 → 拖動時其他圖即時讓位 → 放手落位（D-082，見 `ImageReorder`）。
- **影片／GIF**：GIF 自動循環播放（靜音）；影片列表不自動播，點開詳情才播（D-080）。
- **底部導覽列**：坑／時間軸／我的（D-111）。目前所在分頁的 icon 與文字都用主色、字重 700；子頁面跟隨所屬分頁亮起。
- **哪些頁面有導覽列**（以 artboard 為準，有畫 `<nav>` 才有）：
  - **有**：主頁、坑內頁、六個列表頁（官方圖冊、同人圖、摸魚列表／九宮格、腦洞、成圖、推活兩種佈局）、目標（年／月／日）、我的、空白狀態頁。
  - **沒有**：所有新增／編輯頁、詳情頁、圖片預覽、多選、管理分組、管理 tag、選擇封面、年度回顧排版、主題、備份與同步、登入流程。
  - 簡單規則：**瀏覽用的頁面有，做事用的頁面（填表、看單一項目、選取、設定）沒有。**
- **表單的 tag 欄**旁有「管理」→ `TagManage`。
- **選中狀態**統一：2px 主色框＋22px 實心主色圓圈白剔。
- **圓角**：文字卡片 16px、圖片格 12px、chips 999px、按鈕 14px。
- **詳情頁圖片框**（D-073）：框比例＝最瘦長那張圖（夾在 1.91:1～3:4），圖片 contain 不裁切、留白 `#EFE8DE`；頁碼「1 / N」在框右上角；縮圖一律正方形裁切。
- **刪除**一律要確認（設計稿未畫確認框，用系統 dialog 或 bottom sheet；**popup 不要頂部小橫杆**）。

- **Snackbar**（D-114）：反色、圓角 14、左右 16px；永遠浮在導覽列／底部動作列／固定按鈕上方 12px，不可以蓋住按鈕；3 秒（有「復原」5 秒）；表單裡的中途操作不出。
